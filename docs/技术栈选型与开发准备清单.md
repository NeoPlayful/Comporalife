# Comporalife（复利人生）技术栈选型与开发准备清单

> 项目定位：开源个人财富管理、复利与投资风险模拟平台  
> 产品版本：Comporalife Personal（开源、自部署）；Comporalife Cloud（未来独立闭源商业产品）  
> 文档范围：完整个人版技术方案与开发准备，不按 MVP、P0/P1/P2 或 Phase 划分优先级。  
> 参考格式：SoloShop《技术栈选型与开发准备清单》；业务内容以 Comporalife 为准。

## 三、开发环境设置

### 环境准备

- 安装受支持的 Node.js LTS、npm、Docker Engine 与 Docker Compose v2。
- 开发机可使用 Windows + WSL2、macOS 或 Linux；统一 UTF-8 编码。
- Git 仓库启用 `.gitignore`，禁止提交 `.env`、账单原件、数据库文件和备份。
- 开发环境使用虚构财务数据，不把真实银行流水提交到测试仓库。

### 本地开发命令

```bash
# 1. 克隆项目（替换为实际仓库地址）
git clone <repository-url> Comporalife
cd Comporalife

# 2. 环境变量
cp .env.example .env

# 3. 启动数据库与 Redis
docker compose up -d postgres redis

# 4. 后端
cd server
npm ci
npx prisma generate
npx prisma migrate dev
npm run seed
npm run dev

# 5. 另一个终端启动前端
cd ../frontend
npm ci
npm run dev
```

**说明：** `npm ci` 需要先提交 `package-lock.json`；首次创建项目时先 `npm install` 生成锁文件。`npm run seed`、`npm run dev` 等脚本需在 `package.json` 中定义。

### 环境变量清单

| 名称 | 用途 | 注意事项 |
|---|---|---|
| `NODE_ENV` | 运行环境 | production/development |
| `DATABASE_URL` | PostgreSQL 连接 | 私密配置 |
| `REDIS_URL` | Redis 连接 | 私密配置 |
| `JWT_SECRET` / `JWT_PRIVATE_KEY` | JWT 签名密钥 | 高熵、不得入库；依选定签名算法使用 |
| `COOKIE_SECURE` | Cookie HTTPS 策略 | 生产必须开启 |
| `APP_BASE_URL` | 对外访问地址 | 用于重置密码链接 |
| `UPLOAD_DIR` | 账单上传目录 | 只允许 API 授权读取 |
| `MAX_IMPORT_BYTES` | 导入文件大小限制 | 配合 Nginx 与 Fastify 限制 |
| `DEFAULT_CURRENCY` | 默认展示币种 | 用户可覆盖 |
| `SMTP_HOST` 等 | 邮件服务 | 凭证不可输出到日志 |
| `SIMULATION_MAX_PATHS` | 模拟路径上限 | 防止 CPU 滥用 |
| `SIMULATION_MAX_YEARS` | 模拟期限上限 | 参数校验 |

## 四、核心模块与技术实现

| 模块 | 技术职责 | 数据与计算要点 |
|---|---|---|
| 用户与认证 | Fastify + jose + Argon2id | 用户独立数据访问、会话刷新、密码重置 |
| 财务仪表板 | React + ECharts | 资产、负债、净资产、现金流、投资配置 |
| 财务账户 | Prisma + PostgreSQL | 账户币种、余额、账户类型、期初余额 |
| 交易流水 | 事务 + 分录模型 | 收入、支出、转账、退款、调整 |
| 银行账单导入 | Multipart + CSV/XLSX 解析 + BullMQ | 字段映射、预览、去重、回滚、审计 |
| 分类与预算 | 规则引擎 + PostgreSQL | 用户自定义分类、周期预算、异常提示 |
| 收支分析 | 聚合查询 + ECharts | 现金流、分类占比、月度趋势 |
| 投资管理 | 组合、持仓、交易表 | 买卖、分红、费用、成本基础、收益 |
| 复利模拟 | decimal.js + 计算模块 | 本金、定投、收益率、通胀、提款、税费假设 |
| 蒙特卡罗模拟 | Worker Threads + BullMQ | 随机种子、分布假设、分位数、回撤、尾部风险 |
| 财富目标 | 情景计算 + 目标模型 | 退休、财务自由、目标达成概率 |
| 汇率与币种 | 汇率快照 + Decimal | 原币保存、折算币种、汇率日期 |
| 报表与导出 | 异步任务 + CSV/XLSX | 用户授权、导出审计、过期清理 |
| 备份与恢复 | pg_dump + 加密归档 | 全库备份与恢复验证；多用户权限隔离 |

### 重要财务规则

1. **账户间转账不是消费**：同一笔资金从银行转入证券账户，不计为家庭/个人支出。
2. **信用卡还款不是二次消费**：原始刷卡消费计入支出，还款只清偿负债。
3. **买入证券不是消费**：现金与投资资产之间转换；佣金、税费可单独记账。
4. **收入与资产增长分开**：工资收入、资本利得、未实现盈亏不可混为同一现金流指标。
5. **每个用户数据独立**：所有财务数据访问由后端从已验证身份获取 `userId`，不信任客户端传入的归属 ID。
6. **金额使用 NUMERIC/Decimal**：不可直接使用 JavaScript 浮点数累计账本金额；汇率与数量使用单独精度策略。
7. **模拟不改真实账本**：场景参数和模拟结果独立存储，不生成真实交易。
8. **历史收益不保证未来收益**：模型必须显示假设、费用、通胀和风险提示。

### 复利模拟计算规范

- 参数：初始本金、定期投入金额、投入频率、名义年化收益率、投资期限、复利频率、通胀率、定期提款、费用及税务假设。
- 输出：期末名义价值、通胀调整后的实际价值、累计投入、投资收益、逐期现金流、目标达成情况。
- 约定：明确投入发生在期初还是期末，收益率转换方式、负收益处理与现金流顺序。
- 对比：多个场景可并排比较，但场景间参数和结果独立保存。
- 校验：零利率、负利率、提前提款、资金耗尽、极长期限、精度溢出等边界条件。

### 蒙特卡罗计算规范

- 输入：初始资产、定投/提款、年限、期望收益、波动率、资产配置、相关性假设、模拟次数与随机种子。
- 模型：明确采用何种收益分布（例如对数正态或历史重采样），并记录版本；不把正态收益直接当作确定事实。
- 输出：中位数、P5/P25/P75/P95、目标达成概率、亏损概率、最大回撤分布、尾部风险与资金耗尽概率。
- 执行：API 创建任务，BullMQ 调度 Worker Threads；支持进度、取消、超时、并发上限和资源限制。
- 可复现：保存模型版本、参数、随机种子和模拟路径数；相同配置应可复验。
- 统计：区分终值分位数与整段路径的最大回撤，避免错误混用。

### 账单导入工作流

```text
上传文件 → 类型/大小检查 → 安全解析 → 字段映射 → 标准化
         → 重复识别 → 预览人工确认 → 数据库事务提交
         → 分类与转账匹配 → 统计重算 → 导入批次审计
```

- CSV 编码、分隔符、日期格式、金额正负号、借贷列、账户币种必须可配置或可识别。
- 不自动信任银行导出格式；保留原始行号和来源指纹以便定位问题。
- 使用批次级幂等键与行级去重指纹；允许用户处理疑似重复项。
- 取消导入需要考虑导入后用户已经编辑、关联或对账的记录，不应粗暴级联删除。
- 账单原件默认私有存储，可设置自动删除保留期。

## 五、安全措施

| 领域 | 必要措施 |
|---|---|
| 认证 | Argon2id 密码散列、登录限流、会话过期、密码重置令牌一次性使用 |
| Cookie | HttpOnly、SameSite、生产 Secure；状态变更请求启用 CSRF 防护 |
| 数据隔离 | 所有账户/流水/模拟记录按服务端 `userId` 授权；对象级访问检查 |
| 文件上传 | 文件大小与格式白名单、内容嗅探、解析资源限制、拒绝路径穿越 |
| Excel 安全 | 不执行宏、不信任公式、导出时防 CSV 公式注入 |
| 财务数据 | 敏感字段日志脱敏、最小权限、数据库备份加密、HTTPS |
| 数据库 | 参数化查询、事务、一致性约束、迁移审核、最小权限数据库账号 |
| API | Zod/schema 校验、统一错误码、速率限制、分页上限 |
| 计算资源 | 模拟次数上限、任务并发限制、超时、取消、CPU/内存保护 |
| 审计 | 登录、导入、删除、恢复、导出等敏感操作记录 |
| 供应链 | 依赖锁文件、漏洞扫描、许可证检查、容器镜像固定版本 |
| 隐私 | 账户删除、数据导出、账单原件删除、保留策略、隐私说明 |

**特别注意：** 金融数据属于高敏感度信息。个人版支持多用户注册时，不能仅依靠前端隐藏页面或传入 `userId` 来隔离数据；必须在后端每次读写时执行授权。

## 六、部署方案

### Docker Compose 服务

```yaml
services:
  postgres:  # PostgreSQL 16；持久化卷
  redis:     # Redis 7；缓存和队列
  api:       # Fastify 5；内部 API
  worker:    # BullMQ 任务消费者；与 API 复用服务代码
  nginx:     # 前端静态资源 + /api 反向代理，宿主机 :3000
```

> 上述是服务规划示意，不是可直接执行的完整 Compose 配置。生产需补充镜像、环境变量、卷、网络、健康检查和资源限制。前端由构建阶段生成静态文件并交给 Nginx，不必在生产环境常驻 Vite 开发服务器。

```text
│   ├── postgres/
│   └── redis/
└── backups/               # 加密归档
```

### Nginx 路由

```text
/             -> React 构建静态文件（SPA fallback）
/api/*        -> Fastify API
```

- 不把 `/uploads` 映射为公网静态目录；下载必须走鉴权 API。
- PostgreSQL 和 Redis 仅接入内部 Docker 网络。
- Nginx 配置 TLS 终止方案或部署在可信 HTTPS 反向代理之后。
- 使用健康检查、优雅关闭、数据库备份及恢复演练。
- Worker 可单独伸缩，但个人版无需预设多节点分布式架构。

## 九、开源个人版与商业 SaaS 的代码边界

| 能力 | Personal 开源仓库 | Cloud 私有仓库 |
|---|---|---|
| 财务账本、账单导入、收支分析 | 完整提供 | 复用/集成 |
| 投资组合、复利、蒙特卡罗 | 完整提供 | 复用/集成 |
| 独立用户账号与数据隔离 | 完整提供 | 复用/扩展 |
| 家庭成员邀请与共享授权 | 不纳入个人版 | 商业扩展 |
| SaaS 租户、套餐、计费 | 不纳入个人版 | 商业扩展 |
| 云托管、自动扩容、商业运维 | 用户自部署 | 商业扩展 |

- 不因未来 SaaS 需要而在个人版引入 `tenant_id` 或复杂 RBAC。
- 把业务计算与 HTTP、认证、持久化尽量解耦，以便未来复用。
- 对外开源许可证与闭源复用策略应在接收外部贡献前明确；Apache-2.0/MIT 允许第三方商业复用，不能阻止他人合法托管。
- 不在公开仓库提交商业私钥、运营配置或商业专有模块。

## 十、总结与完成标准

| 维度 | 完成标准 |
|---|---|
| 技术栈 | React 19、Vite 8、Tailwind 4、Fastify 5、Prisma、PostgreSQL 16、Redis 7 可稳定协作 |
| 业务 | 账户 → 账单 → 收支 → 投资 → 复利/风险模拟 → 财富目标全链路可用 |
| 准确性 | 账本无重复计数、金额精确、模拟假设明确、结果可复现 |
| 安全 | 用户数据隔离、上传安全、导出授权、敏感日志脱敏 |
| 部署 | Docker Compose 自部署、升级迁移、备份与恢复可验证 |
| 开源 | 完整个人版可运行，代码、许可证、文档与测试齐备 |
| 扩展 | 保留闭源 SaaS 复用空间，不提前实现商业多租户与订阅 |

**项目核心标准：** Comporalife 不是单一的复利计算器，而是可独立部署、数据归用户掌控的个人财富管理与投资模拟系统。技术选型应优先保障财务数据正确性、隐私、安全、计算可复现性和长期维护能力。
