# Comporalife（复利人生）

开源自部署的个人财富管理工具：**银行账单 → 收支分析 → 可投资结余 → 复利与风险模拟 → 财富目标与报表 → 数据导出、备份与恢复**。

数据保存在你自己的部署里，不做云端托管，不建租户与家庭共享。

## 账单导入

支持 CSV（UTF-8 / GBK）与 XLSX，单文件上限 10 MB、20,000 行。

导入流程是「上传 → 映射 → 预览校验 → 重复确认 → 提交」，未确认前不会写入账本：

1. **上传**：文件加密存放在配置的存储目录，按表头签名自动推荐映射模板。
2. **映射**：选择日期列、金额模式（单列有符号或借贷两列）、日期格式等。日期存在「日/月」歧义时强制显式选择，不自动猜测。
3. **校验**：逐行给出错误原因；与已有交易完全相同的行为「重复」，同额同日但摘要不同的为「疑似重复」。
4. **确认**：完全重复默认跳过，疑似重复必须逐条确认。
5. **提交**：单事务写入，支持 `Idempotency-Key`，失败整体回滚。

已提交的批次可整批撤销：批次内交易被冲正、指纹释放，可重新导入同一文件。若交易已被手工修改、已匹配为转账，或账户在导入后产生过对账记录，撤销会被拒绝并给出原因。

示例账单见 `examples/`，全部为虚构数据。

**隐私**：原始账单文件使用 AES-256-GCM 加密，密钥来自环境变量，不进入日志、不对外提供下载，默认在提交 30 天后清理文件（交易与行记录保留）。

**不支持**：OFX/QFX 与 PDF 账单；跨币种账单（币种与账户不一致的行会报错而非静默折算）。

## 投资组合与收益

投资模块把「转到证券账户的钱」变成可核对的对象，同时**绝不污染收支统计**。

**口径**：

- 买入、卖出是资产转换，账本类型为 `investment`，**不计入收入与支出**。
- 股息、利息计入收入；手续费、税费计入支出。
- 入金、出金同样走账本（`investment` 类型），因此组合现金能反映真实余额，且不影响收支。
- 组合价值 = 账户现金 + 证券市值。证券账户的现金已计入净资产，组合侧只加市值，**不重复计算**。

**持仓与损益**：

- 成本法为加权平均：买入时 `总成本 += 成交额 + 手续费`；卖出不改变单位成本。
- 持仓、成本、损益全部由交易历史重放得出，不存快照；修改历史交易后结果立即正确。
- 卖出按成交日校验持仓，历史超卖会被拒绝并给出当日可用数量。
- 已实现损益使用**卖出当时**的平均成本，不是今天的成本。

**估值**：

- 本期只支持手工录价，同一标的一天一个价格，重复录入即覆盖。
- 价格超过 7 天标记为过期（`INVESTMENT_PRICE_STALE_DAYS`），界面显示标签而不是当作实时行情。
- 没有价格的标的市值按 0 计并列入缺失清单，**绝不按成本价冒充市值**。

**收益**：

- **TWR**（时间加权）剔除入金出金的影响，衡量策略本身。
- **XIRR**（资金加权）反映真实资金的时间价值，包含择时。
- 两者并列展示；不可计算时返回 `—` 与原因（数据不足、缺价、现金流方向单一、未收敛），**不会显示 0%**。
- 新建组合的历史价格不可回填，因此 TWR 通常从你开始录价之后才有值，这是数据可得性限制而非缺陷。

**不交付**：行情自动接入、FIFO/指定批次成本法、外币计价标的、分红再投资、期权与融资融券、投资交易专用导入、自动再平衡下单。

## 风险模拟

复利引擎只能回答「假设每年正好 7%」。风险模拟用随机市场路径取代单一曲线，给出**区间与概率**而不是一个点估计。

**模型**：

- 收益服从对数正态，按月离散；月度漂移为 `ln(1+R)/12 − σ²/2`。
- 减去 σ²/2 是必须的：否则波动会把期望收益系统性抬高。零波动时结果与复利引擎严格一致，这条作为长期回归用例。
- 多资产用相关系数矩阵，经 Cholesky 分解生成相关随机数；矩阵非正定直接拒绝，不做静默修正。
- 再平衡频率显式记录（不再平衡/每月/每季/每年），因为它显著影响结果。

**结果口径**：

- 终值给出 P5/P10/P25/P50/P75/P90/P95，名义与实际（通胀折算）各一套，另附均值与标准误。
- 概率包括名义亏损、实际亏损、达标（未设目标时为 `null`，不返回 0）与破产。
- 最大回撤基于投资增长指数计算，**不含追加投入**——持续定投会掩盖回撤，用账户值算会系统性低估风险。
- 任何结果都必须能看到样本量与标准误，样本不足时界面明确提示分位数波动较大。

**异步执行**：

- 运行入队后由进程内执行器按时间预算分片执行，片间让出事件循环，不阻塞其他请求。
- 作业状态以数据库为唯一权威，取消是一次 `UPDATE`，进度单调不减。
- 进程重启后心跳超时的运行自动回到队列，种子不变因此重算结果与首次一致；重试两次仍失败则置为失败。
- 同一 `seed` + 同一参数快照 + 同一 `modelVersion` 结果逐位一致；跨 V8 版本末位可能不同，因此结果落库后不再重算。

**压力情景**：崩盘、滞胀、失去的十年是确定性单路径，与随机结果分开呈现，不参与分位数，也没有「达标概率」的含义。

**模拟永不入账**：运行前后账户余额、交易条数、净资产完全不变。

**不交付**：财富目标、报表导出、多实例分布式调度、跳跃扩散/厚尾等进阶收益模型、逐月递增定投与提款。

## 财富目标

目标的价值在于**和真实数据绑定**：进度只能由账本与投资组合推导，接口不接受手填百分比，改了历史流水进度立即跟着变，没有后台刷新任务。

**资金绑定**：可选择整体净资产（用增量而非绝对值，避免目标创建前就有的房贷把进度拉成负数）、单个账户余额，或投资组合市值（含绑定账户现金 + 证券市值，与净资产口径一致，不重复计算）。

**口径要点**：

- 进度不封顶，超额完成保留真实数值，界面封顶 100% 但悬停可见真实值。
- 达成的「首次达成时间」按月重算，并在界面标注：实际达成可能发生在该月内更早的日期。
- 绑定的账户或组合被归档时，进度返回 `null` 并标注不可用，不会静默归零。
- 通胀调整是显式开关，开启后同时展示原始目标与调整后目标。

**预测必须分源并列**：

- 点估计来自复利引擎（与复利模拟页同一套公式），给出预计达成时间与所需月供；反推用二分求解，结果可回代验证。
- 区间与概率来自蒙特卡罗，且**只取目标金额、年限、币种三者都匹配的最近一次成功运行**。没有匹配运行时显示「暂无匹配的模拟」并给出需要什么样的运行，绝不借用不相干运行的概率。
- 两张卡片在视觉上分离，分别标注来源，永不加权合并成一个数字。

**财务自由**：年化支出取最近 12 个完整月，不足 6 个完整月时所有派生指标返回 `null`；覆盖月数在支出为 0 时返回 `null` 而不是无穷大；页面只给指标与提取率敏感性，不出现「可以退休」这类结论。

## 财务报表

报表是**快照**：生成那一刻冻结参数、口径与数据；之后账本再变，历史报表也不会悄悄变形。要看最新数据必须显式「重新生成」。

**六类报表**：资产负债、现金流量、收支分析、投资绩效、目标进度、模拟分析。

**口径对象**（随每份报表返回）：

- 统计区间、基准币种、汇率日期、账户范围。
- 完整性：缺失月份、缺失汇率、过期估值、无价标的逐项列出；任一项缺失即标记不完整，界面用警示色展示。
- 引用到的模型版本（`compound-v1` / `montecarlo-v1`）与生成时间。

**导出**：

- CSV 为 UTF-8 带 BOM（否则中文 Windows 的 Excel 会乱码），RFC 4180 转义，`

` 换行。
- 公式注入防护：以 `= + - @` 开头的**文本**加单引号前缀；判定前先按数值解析，因此负数不会被误伤。
- 数值列导出原始数值，不加千分位与币种符号，Excel 中可直接求和。
- 文件名同时提供 ASCII 回退名与 RFC 5987 中文名（`filename*`）。
- 导出全程只读，只额外写一条审计事件。

**模拟结果导出**：文件首区块固定包含 `modelVersion` 与 `seed`——脱离这两项，蒙特卡罗结果无法解读。

## 核心设计约定

这几条不是可选风格，而是产品正确性的前提：

1. **账本用复式分录**。收入与支出配一条外部对手方分录，转账是两条真实账户分录；每笔交易求和必须为零，否则整笔回滚。
2. **余额不冗余存储**。账户余额 = 期初余额 + 已入账分录之和，避免两套权威数据。
3. **交易不物理删除**。删除语义是冲正，分录保留，历史可追溯。
4. **转账、信用卡还款、投资买入都不是消费**。内部转账单独统计，不进入收入或支出。
5. **金额全程 Decimal**。数据库 `DECIMAL(20,6)`，后端 `decimal.js`，API 传输字符串，不用浮点。
6. **模拟结果不落库**。参数确定则结果确定，读取时实时计算，防止结果与参数不一致。
7. **缺失汇率不猜**。缺少汇率时相关账户从折算中排除并显式提示，不按 1:1 处理。
8. **统计必须带口径**。所有指标随数值返回时间区间、基准币种、时区与数据完整性标记。
9. **投资不是收支**。买入卖出只做资产转换；只有股息利息（收入）与手续费税费（支出）进入收支统计。
10. **收益不可算就留空**。TWR / XIRR 在数据不足或缺价时返回 `null` 并附原因，绝不返回 0。
11. **目标进度不可手填**。进度只由账本与组合推导，改历史流水立即生效，没有手工进度字段。
12. **报表生成即冻结**。快照与口径同时落库，重新生成是显式动作，历史报表不会随时间变形。
